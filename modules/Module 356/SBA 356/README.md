# SBA 356 - Python Essentials 2 — Personal To-Do List Manager

**Name:** James Sloan
**Course:** Python Essentials (UCI 3052)
**Date:** September 13, 2026

A small three-module to-do list app: a `Task` class, a set of list/file
operations that work on plain lists of `Task` objects, and a text menu
that ties them together. Tasks persist to a CSV file between runs.

## Files

| File | Purpose |
| --- | --- |
| `task.py` | Task 1 — the `Task` class: `title`, `due_date`, `completed`, and `__str__()` for display. |
| `todolist.py` | Tasks 2 & 4 — `add_task()`, `complete_task()`, `delete_task()`, `list_tasks()` (with overdue detection), plus `load_tasks()`/`save_tasks()` for CSV persistence. |
| `main.py` | Task 3 — the menu loop (A/C/D/L/Q) that calls into `todolist.py`. No file I/O of its own — it's a thin UI layer. |

## Design

- **`Task` is a plain data class.** `due_date` is stored as a real
  `datetime.date` (or `None`), not a string, so `list_tasks()` can compare
  it directly against `date.today()` for the overdue check.
- **`todolist.py` owns every list and file operation.** `main.py` never
  touches `tasks` except to pass it into these functions — that's the
  "modularized into a separate module" the rubric asks for.
- **Persistence uses the standard `csv` module**, one row per task:
  `title,due_date,completed`. An empty `due_date` field round-trips to
  `None`.
